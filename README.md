# لوحة إدارة المشاريع الذكية

نظام لوحة تحكم وإدارة مشاريع بلغة PHP الخام (بدون أي إطار عمل خارجي) وقاعدة
بيانات MySQL، بتثبيت تلقائي كامل، إدارة مستخدمين وصلاحيات، وقسم "معرفة
المشروع" يربط كل مشروع بهيكل قاعدة بياناته وقواعده البرمجية ومستودع GitHub
الخاص به، مع مساعد ذكي بوضعين لكل مشروع: **دردشة عادية** (نص ورؤية، سياق
المشروع يُحقن تلقائياً)، و**وضع الكود** الذي يستكشف مستودع GitHub المرتبط
تلقائياً (أشبه بـ Claude Code) لحل المشاكل بناءً على محتوى الملفات الفعلي.

مزوّدو الذكاء الاصطناعي (عدة مفاتيح NVIDIA NIM، أو أي مزوّد آخر متوافق مع بنية
OpenAI Chat Completions API مثل OpenAI وGroq وDeepSeek) **عامّون على مستوى
النظام كله** ويديرهم الأدمن حصراً من صفحة واحدة، وتشاركهم كل المشاريع، مع تتبّع
تلقائي لعدد التوكنات المستهلكة وحد اختياري لكل مزوّد. ردود الدردشة العادية
تظهر **تدريجياً كلمة بكلمة** (Streaming) بدل انتظار الرد كاملاً (مع إعادة
محاولة صامتة واحدة تلقائياً عند انقطاع اتصال فعلي قبل وصول أي جزء من الرد —
شائع على شبكات الجوال المتقطّعة — بدل إظهار خطأ فوراً)، وتُنسَّق
بأسلوب Markdown (عناوين، جداول، قوائم، كود) بدل نص خام. المزوّد المختار لكل
محادثة **يُحفظ ويبقى نفسه** تلقائياً عند إرسال رسائل تالية أو حتى بعد إغلاق
المشروع وإعادة فتحه، وصورة أُرسلت لمزوّد نصّي بحت (بلا نموذج رؤية) تُوصَف أولاً
تلقائياً عبر أي مزوّد آخر يملك نموذج رؤية ثم يُمرَّر الوصف كنص عادي للمزوّد
المختار فعلياً — بذلك تعمل الصور حتى مع مزوّدين نصيين بحتين. ربط GitHub يتم عبر
**OAuth حقيقي** (زر "ربط GitHub" لكل مستخدم) بدل لصق Personal Access Token
يدوياً، مع **قائمة اختيار مستودع فعلية** من مستودعات حساب المستخدم بدل كتابة
Owner/Repo يدوياً. **وضع الكود يعمل كمساحة عمل حقيقية**: يرفع أي تعديل يطلبه
المستخدم كـ Commit تلقائي مباشر على المستودع بنفسه (بلا نسخ/لصق يدوي)، ضمن
محادثة واحدة مستمرة لكل مشروع (بلا رواق محادثات متعددة). كل مشروع يملك أيضاً
تبويب **"Skill"** مستقلاً بمقتطفات سياق دائمة **متعددة** (كل واحد بعنوانه، قابل
للإضافة والتعديل والحذف) تُحقن تلقائياً في كل رسالة. **مشاريع كل مستخدم خاصة
به** ولا تظهر لغيره (الأدمن وحده يرى الجميع). يمكن للمستخدمين إنشاء حساباتهم
بأنفسهم، وقاعدة البيانات تُحدَّث تلقائياً بضغطة واحدة عند صدور تحديثات جديدة
(بلا SQL يدوي).

الواجهة مبنية بتصميم أسود (أو أبيض — **وضع داكن/نهاري قابل للتبديل** من القائمة
الجانبية، يُحفظ الاختيار في المتصفح) بأسلوب شبيه بتطبيق Claude تماماً: **قائمة
جانبية واحدة موحَّدة** تجمع كل شيء (لا شريط تبويبات منفصل داخل صفحة المشروع):
التنقّل العام، ثم عند فتح مشروع تظهر تبويباته الأربعة (الدردشة العادية/الكود/
Skill/الإعدادات) مباشرة تحت "المشاريع"، تليها قائمة قابلة للتمرير بمشاريعك
الأخرى للتبديل السريع بينها، وفي الأسفل زر الوضع الداكن/النهاري وبطاقة
المستخدم وزر تسجيل خروج واضح المعالم بنص صريح — على الهاتف تُفتح هذه القائمة
نفسها بالكامل عبر زر الهامبرغر بدل شريطين منفصلين. داخل المساعد الذكي رواق
محادثات + لوحة دردشة (تقسيم شاشة من مستويين، في وضع الدردشة العادية)، مع أزرار
ملوّنة لكل إجراء (أساسي/نجاح/خطر/تحذير)، وخط IBM Plex Sans Arabic، ودعم كامل
لـ RTL ولشاشات الكمبيوتر المحمول والهواتف.

## المتطلبات

- PHP 8.1+ مع امتدادات: `pdo_mysql`, `curl`, `openssl`, `json` (مفعّلة افتراضياً في أغلب الاستضافات)
- MySQL 5.7+ أو MariaDB 10.3+
- خادم Apache (مرفق ملفات `.htaccess` جاهزة) أو Nginx/PHP-FPM
- لا حاجة لـ Composer أو أي حزم Node — المشروع PHP خام بالكامل

## التثبيت

1. ارفع محتويات المشروع إلى السيرفر (أو استنسخه داخل مجلد الاستضافة).
2. تأكد أن مجلد `config/` قابل للكتابة من قبل خادم الويب (سيُنشئ فيه المثبّت ملف `config.php`).
3. افتح المشروع من المتصفح — إن لم يوجد `config/config.php` سيتم توجيهك تلقائياً إلى `install.php`.
4. أدخل بيانات الاتصال بقاعدة البيانات (Host, Port, Name, User, Password). إن لم تكن قاعدة البيانات موجودة سيتم إنشاؤها تلقائياً (أو استخدام الموجودة إن لم تسمح صلاحيات المستخدم بإنشائها، كما هو الحال في بعض الاستضافات المشتركة).
5. أدخل بيانات حساب المسؤول الرئيسي (Admin): الاسم، البريد الإلكتروني، كلمة المرور.
6. عند الضغط على "ابدأ التثبيت" يقوم النظام بـ:
   - إنشاء/استخدام قاعدة البيانات وتنفيذ `database/schema.sql` بالكامل (كل الجداول بصيغة `IF NOT EXISTS`).
   - إنشاء حساب المسؤول بكلمة مرور مشفّرة (`password_hash` بخوارزمية BCRYPT).
   - توليد مفتاح تشفير عشوائي (32 بايت) وكتابة `config/config.php` تلقائياً.
7. سيتم توجيهك لصفحة تسجيل الدخول. سجّل الدخول بحساب المسؤول وابدأ العمل.

> لإعادة التثبيت من الصفر، احذف ملف `config/config.php` يدوياً من السيرفر.

### التثبيت اليدوي (اختياري)

يمكن نسخ `config/config.sample.php` إلى `config/config.php` وتعديله يدوياً، مع
استيراد `database/schema.sql` وإنشاء مستخدم مسؤول يدوياً عبر SQL باستخدام
`password_hash()` في PHP لتوليد كلمة المرور.

## معايير الأمان المطبّقة

- **PDO + Prepared Statements حصراً** في كل استعلام بقاعدة البيانات (`ATTR_EMULATE_PREPARES = false`) — لا استعلامات مُركَّبة من نصوص خام.
- **كلمات المرور**: `password_hash()` بخوارزمية BCRYPT، ومقارنة بـ `password_verify()`.
- **حماية CSRF**: رمز عشوائي 32 بايت لكل جلسة، يُتحقق منه في كل نموذج POST وكل طلب AJAX عبر ترويسة `X-CSRF-Token`.
- **حماية XSS**: تنظيف كل المخرجات عبر `htmlspecialchars()` (دالة `e()`)، وواجهة المساعد الذكي تبني عناصر DOM عبر `textContent` حصراً بدل `innerHTML` لأي نص قادم من المستخدم أو من رد النموذج الذكي.
- **جلسات آمنة**: أسماء جلسة مخصّصة، `HttpOnly` + `SameSite=Lax` + `Secure` عند HTTPS، `session_regenerate_id()` عند تسجيل الدخول، ومهلة خمول تلقائية.
- **الحماية من هجمات التخمين (Brute-force)**: قفل مؤقت بعد 5 محاولات فاشلة لكل مزيج (IP + بريد إلكتروني).
- **تشفير الأسرار في قاعدة البيانات**: مفاتيح كل مزوّدي الذكاء الاصطناعي (`ai_providers.api_key`)، رمز وصول GitHub OAuth لكل مستخدم (`users.github_oauth_token`)، وClient Secret الخاص بتطبيق GitHub OAuth (`app_settings`) — كلها مشفّرة (AES-256-GCM) بمفتاح مولَّد تلقائياً أثناء التثبيت ومحفوظ في `config/config.php` فقط (خارج المستودع). القيم المشفّرة **لا تُفَكّ ولا تُعرض للمتصفح إطلاقاً** بعد الحفظ — الحقول تظهر فارغة مع إشعار "محفوظ".
- **مفاتيح الـ API لا تصل للمتصفح مطلقاً**: كل نداء لـ GitHub ولأي مزوّد ذكاء اصطناعي يتم من السيرفر (PHP) حصراً؛ متصفح المستخدم لا يرى المفتاح لا في HTML ولا في طلبات AJAX.
- **ربط GitHub عبر OAuth حقيقي**: بدل لصق Personal Access Token يدوياً، يربط كل مستخدم حسابه عبر Authorization Code Flow القياسي (`github_oauth_start.php` → GitHub → `github_oauth_callback.php`)؛ رمز `state` عشوائي بالجلسة يمنع CSRF، ومسار العودة (`return`) يُتحقَّق منه بتعبير نمطي صارم يمنع Open Redirect.
- **صلاحيات الوصول**: `users.php`، `ai_providers.php`، و`admin_settings.php` محمية بـ `require_admin()` (الأدمن حصراً — يدير المزوّدين وتطبيق GitHub OAuth). صفحات المشاريع محمية بـ `require_login()` مع تحقق إضافي من الملكية أو دور المسؤول قبل الأرشفة أو الحذف.
- **خصوصية المشاريع**: كل مشروع مرئي لمالكه فقط (والأدمن). `project_context.php` يتحقق من الملكية قبل عرض أي بيانات، وكل نقاط `api/*.php` التي تستقبل `project_id` تستخدم `require_project_access()` لرفض أي وصول من مستخدم لا يملك المشروع (404/403 حسب الحالة) قبل تنفيذ أي استعلام.
- **ترويسات أمان HTTP**: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Content-Security-Policy`, `Permissions-Policy` على كل صفحة. `script-src` في CSP صارم (`'self'` فقط) بلا `unsafe-inline`؛ السكربت المضمَّن الوحيد الضروري (كشف الوضع الداكن/النهاري المحفوظ قبل الرسم الأول لتفادي الوميض) مسموح تحديداً عبر CSP nonce عشوائي لكل طلب (`csp_nonce()`) بدل إضعاف السياسة لكل السكربتات المضمَّنة.
- **حماية على مستوى الملفات**: `.htaccess` يمنع الوصول المباشر لمجلدات `config/` و`includes/` و`services/` و`database/` وأي ملف إعداد أو SQL.

## مزوّدو الذكاء الاصطناعي (عامّون على مستوى النظام)

من صفحة **"مزوّدو الذكاء الاصطناعي"** (`ai_providers.php`، للأدمن فقط) تُدار
كل مزوّدي الذكاء الاصطناعي على مستوى النظام كله — لا لكل مشروع على حدة. يمكن
إضافة أي عدد من المفاتيح: أكثر من مفتاح NVIDIA NIM (للتبديل بينها أو كنسخة
احتياطية)، أو أي مزوّد آخر متوافق مع بنية OpenAI Chat Completions API (OpenAI،
Groq، DeepSeek، Together AI، OpenRouter، Mistral، أو نموذج مستضاف ذاتياً)
بتحديد نقطة الاتصال (Base URL) الخاصة به. كل مزوّد له تسمية، مفتاح API خاص،
نموذج نص، ونموذج رؤية اختياري، ويمكن تعيين واحد كـ"افتراضي". هذه القائمة
مشتركة بين كل المشاريع وكلا وضعي المحادثة — من تبويبَي "الدردشة العادية" و"الكود"
في كل مشروع تظهر قائمة منسدلة لاختيار أي مزوّد مُسجَّل تريد استخدامه لكل رسالة.

## ربط حساب GitHub (OAuth)

1. **إعداد لمرة واحدة (أدمن):** من صفحة "إعدادات النظام" (`admin_settings.php`)،
   سجّل تطبيق OAuth من `github.com/settings/developers` → New OAuth App، بحقل
   Authorization callback URL مطابق تماماً لما تعرضه الصفحة، ثم احفظ Client ID
   وClient Secret الناتجين هناك.
2. **لكل مستخدم:** زر "ربط حساب GitHub" (في تبويب "السياق والإعدادات" لأي مشروع،
   أو من "حسابي") يحوّل إلى GitHub لتفويض الوصول (Authorization Code Flow
   القياسي)، ثم يعود ويخزّن رمز الوصول مشفّراً على حساب المستخدم — لا حاجة لإنشاء
   أو لصق Personal Access Token يدوياً بعد الآن. نفس الحساب المرتبط يُستخدم
   تلقائياً لكل مشاريع هذا المستخدم.
3. لكل مشروع، يبقى تحديد **Owner/Organization، اسم المستودع، والفرع** من تبويب
   "السياق والإعدادات" (حقول نصية بسيطة، دون أي Token يدوي).

## تبويبات كل مشروع (`project_context.php`)

تظهر ضمن القائمة الجانبية الموحَّدة نفسها (وليست شريطاً منفصلاً داخل صفحة
المشروع) — راجع وصف القائمة الجانبية أعلاه. أربعة تبويبات:

1. **الدردشة العادية** — محادثة نصية/برؤية متعددة (رواق محادثات + لوحة دردشة)؛
   `AiClient::buildSystemPrompt()` يحقن هيكل قاعدة البيانات وقواعد المشروع
   (القديمة، إن وُجدت من نسخة سابقة) ومقتطفات Skill تلقائياً ضمن System Prompt.
   المزوّد المختار من القائمة المنسدلة **يُحفظ لكل
   محادثة** (ويُستذكر أيضاً محلياً في المتصفح لأي محادثة جديدة لم تُحفظ بعد) —
   لا يتبدّل تلقائياً عند إرسال رسالة تالية أو إعادة فتح المشروع، مع بطاقة صغيرة
   تعرض اسم المزوّد ونموذجه الحالي. صورة تُرسَل لمزوّد بلا نموذج رؤية تُوصَف أولاً
   تلقائياً عبر أي مزوّد آخر يملك نموذج رؤية، ثم يُستكمل الرد بالمزوّد المختار
   فعلياً كنص عادي. زر "رفع إلى GitHub" على أي كتلة كود في رد المساعد لإنشاء
   Commit يدوي مباشر (الملف الموجود يُحدَّث تلقائياً، أو يُنشأ كملف جديد).
2. **الكود** — مساعد أشبه بـ Claude Code، **بمحادثة واحدة مستمرة فقط** لكل
   مستخدم بكل مشروع (بلا رواق أو أزرار "محادثة جديدة" — صفحة واحدة متواصلة).
   يتطلب حساب GitHub مرتبطاً ومستودعاً محدَّداً لهذا المشروع (تُختار مستودعاتك
   الفعلية من قائمة مباشرة بدل كتابة الاسم يدوياً — زر "اختر من مستودعاتك" في
   تبويب الإعدادات). عند كل رسالة يجلب `GithubClient::getTree()` نظرة عامة عن
   ملفات المستودع ويحقنها بموجّه النظام، ثم يعمل بحلقة **محدودة**: إن احتاج
   الاطلاع على ملف معيّن يطلبه بصيغة `READ_FILE: path` (حتى 3 ملفات دفعة واحدة،
   حتى 3 جولات استكشاف إجمالاً). **يعمل المستودع كمساحة عمل حقيقية**: عند طلب
   تعديل فعلي (لا مجرد مثال توضيحي) يكتب المساعد الملف كاملاً بصيغة
   `WRITE_FILE: path` ويرفعه السيرفر مباشرة كـ Commit فعلي عبر
   `GithubClient::createOrUpdateFile()` (حتى 5 ملفات بالرد الواحد) — بلا نسخ
   ولصق يدوي، مع رابط الـ Commit في الرد وملاحظة شفّافة بكل ملف قُرئ أو كُتب.
3. **Skill** — صفحته الخاصة؛ راجع القسم التالي.
4. **الإعدادات** — بيانات المشروع (الاسم/الوصف) وبيانات GitHub (حالة الربط،
   اختيار المستودع، Owner/Repo/Branch) حصراً.

## Skill: سياق دائم متعدد المقتطفات لكل مشروع

تبويب **"Skill"** المستقل لكل مشروع (جدول `project_skills`) يتيح إضافة **أكثر
من مقتطف سياق** دائم، كل واحد بعنوانه الخاص: اكتب نصاً (أو أرفق ملفاً نصياً
`.txt`/`.md`/`.json`/`.csv`/`.log`/`.yml` يُقرأ محتواه في متصفحك مباشرة عبر
`FileReader`) واضغط حفظ ليظهر كبطاقة مستقلة قابلة للتعديل أو الحذف لاحقاً.
كل المقتطفات (دليل أسلوب الفريق، ملخّص API خارجي، أي معرفة ثابتة) تُحقن مجتمعة
تلقائياً ضمن موجّه النظام لكل رسالة في هذا المشروع، بوضعَي الدردشة العادية
والكود معاً، عبر `project_skills_combined()`.

## خصوصية المشاريع

كل مشروع مملوك لمنشئه حصراً: قائمة المشاريع (`projects.php`) ولوحة التحكم
تعرضان لكل مستخدم مشاريعه فقط، وفتح مشروع أو استدعاء أي نقطة `api/*.php` عليه
مباشرة (بمعرفه أو Slug) من مستخدم آخر غير مالكه يُرفض بخطأ صريح — عبر
`require_project_access()` في نقاط الـ API، وتحقّق مماثل في `project_context.php`
نفسها. **الأدمن وحده** يتجاوز هذا القيد ويرى/يدير كل المشاريع.

## استهلاك التوكنات

كل رد ناجح (مُبثّاً كان أو لا) يزيد `ai_providers.tokens_used` تلقائياً وفق
حقل `usage.total_tokens` القادم من المزوّد. من صفحة "مزوّدو الذكاء الاصطناعي"
يمكن للأدمن تحديد **حد شهري اختياري** لكل مزوّد لعرض "المتبقي" وشريط تقدّم
(لا يوجد API موحّد لجلب الرصيد الفعلي من المزوّدين، فهذا الحد يُدخَل يدوياً
حسب ما تعرفه من لوحة تحكم المزوّد نفسه)، مع زر لتصفير العدّاد. إجمالي
الاستهلاك عبر كل المزوّدين يظهر أيضاً كبطاقة على لوحة التحكم للأدمن.

## روابط نظيفة لكل مشروع

كل مشروع يحصل على معرّف عشوائي (`projects.public_slug`، 10 محارف hex) لا
يكشف رقمه التسلسلي الداخلي، وتصبح روابطه `chat/{المعرّف}`، `code/{المعرّف}`،
`skill/{المعرّف}`، و`settings/{المعرّف}` بدل `project_context.php?id=...&tab=...` — عبر قواعد
إعادة كتابة في `.htaccess` (`mod_rewrite`، مفعّل افتراضياً على أغلب استضافات
cPanel). الروابط القديمة بصيغة `?id=` تبقى تعمل أيضاً كخط رجوع إن تعذّرت إعادة
الكتابة على استضافة ما. **ملاحظة تقنية مهمة**: أضفنا وسم `<base href="...">`
في رأس كل صفحة حتى تُحلّ كل الروابط النسبية (القائمة الجانبية، CSS/JS، طلبات
AJAX) من جذر التطبيق دائماً بدل مسار الرابط النظيف المعروض بشريط العنوان —
بدون هذا الوسم تنكسر هذه الروابط عند فتح صفحة عبر رابط نظيف.

## التحديث التلقائي لقاعدة البيانات

لا حاجة لتشغيل أي ملف SQL يدوياً بعد الآن. عند فتح أي صفحة، يتحقق النظام
تلقائياً (`includes/migrations.php`) إن كانت قاعدة البيانات تحتاج أياً من
تحديثات المخطط اللاحقة للتثبيت الأصلي (`ai_providers` العامّة، ربط GitHub
عبر OAuth، `mode` للمحادثات، Skill بعمود وحيد قديم ثم جدول `project_skills`
متعدد المقتطفات (مع ترحيل تلقائي لأي محتوى Skill قديم)، تتبّع التوكنات،
الروابط النظيفة، وعمود `ai_conversations.provider_id`). إن
احتاجت تحديثاً، يرى الأدمن صفحة "قاعدة البيانات تحتاج تحديثاً" بزر واحد
"تحديث قاعدة البيانات الآن" يطبّق كل ما هو ناقص فوراً (كل خطوة آمنة تماماً
على بياناتك الحالية — لا حذف لأي شيء، والجدول القديم عند تحويل مزوّدي الذكاء
الاصطناعي إلى قائمة عامة يُحفظ باسم `ai_providers_old_per_project` بدل حذفه).
غير الأدمن يرى رسالة "النظام قيد التحديث" ودّية بدل صفحة خطأ. ملفات
`database/schema.sql` (لتثبيت جديد) و`database/migrate_global_providers_and_oauth.sql`
(SQL يدوي بديل، إن فُضِّل عدم استخدام الزر) تبقيان متوفرتين أيضاً.
