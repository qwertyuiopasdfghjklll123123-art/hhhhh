# واصل — نسخة PHP + MySQL + بوابة واتساب (Node.js)

نسخة من منصة واصل (الأصل بـ `webapp.py`/Flask/SQLite، لازالت موجودة وتعمل عادي على VPS -
هذا النسخة ما لمستها) مبنية بـ **PHP 8 + MySQL** لتعمل على استضافة مشتركة
(cPanel/DirectAdmin/Hostinger) **بدون VPS**. القسم الوحيد اللي يحتاج Node.js هو بوابة
واتساب (`wasel-gateway/`) - غالب الاستضافات المشتركة الحديثة تدعم تشغيل تطبيق Node.js
صغير بجانب PHP (DirectAdmin: Setup Node.js App، أو CloudLinux Node.js Selector).

## لماذا بوابة واتساب منفصلة؟

`webapp.py` يرسل عبر متصفح Chrome حقيقي (Selenium) يبقى شغال بالخلفية - هذا **غير ممكن
على استضافة مشتركة إطلاقاً** (لا صلاحية تشغيل متصفح، ولا عمليات خلفية دائمة لـ PHP).
البديل: `wasel-gateway/` تطبيق Node.js صغير يتصل بواتساب مباشرة ببروتوكول واتساب ويب
(مكتبة Baileys) **بدون أي متصفح/Chrome** - يحتاج فقط تشغيل Node.js عادي، وهذا متوفر
بأغلب الاستضافات المشتركة الحديثة. موقع PHP يتكلم مع هذه البوابة عبر HTTP فقط.

## البنية (بجذر المستودع - بدون أي مجلد اسمه "php")

```
public/              ← نقطة الدخول (index.php) - هذا يكون DocumentRoot الموقع لو تگدر
core/
├─ config.sample.php ← انسخه إلى config.php واكتب بياناتك (الملف الوحيد الذي تعدّله)
├─ bootstrap.php
├─ lib/              ← قاعدة البيانات، الجلسات، الحماية، التوجيه، عميل بوابة واتساب...
├─ routes/           ← كل مسارات الموقع (auth, accounts, campaigns, subscribers, api_keys, admin...)
└─ templates/        ← واجهة الموقع (welcome.html + app.html)
sql/database.sql     ← قاعدة البيانات كاملة (17 جدول) بملف واحد
tools/               ← init_db.php, create_admin.php
cron.php             ← معالجة الحملات بالخلفية (يُشغَّل من Cron Jobs)
.htaccess            ← يوجّه لـ public/ ويحجب core/ sql/ tools/
public/manifest.json ← PWA (مسار PHP ديناميكي، ليس ملفاً ثابتاً) + sw.js + icon-192/512.png
wasel-gateway/        ← تطبيق Node.js منفصل (بوابة واتساب - Baileys)
├─ app.js
├─ package.json
└─ config.sample.json
```

## المحفظة والتسعير بالرسالة (اختياري)

من لوحة الأدمن ← إعدادات الموقع: حقل **"سعر الرسالة الواحدة"**. بقيمة `0` (الافتراضي)
الإرسال مجاني تماماً كما كان - لا تغيير على أي موقع قائم. بقيمة أكبر من صفر، كل رسالة
حملة أو إرسال عبر API الخارجي يخصم هذا المبلغ من محفظة صاحبها (`users.balance_iqd`)
بعد نجاح الإرسال الفعلي فقط؛ لو الرصيد غير كافٍ **تتوقف الحملة مؤقتاً** (نفس زر "إيقاف
مؤقت") بدل فشل كل رقم تباعاً - يشحن المستخدم رصيده ثم يستأنف من حيث توقف. **حساب
الأدمن معفى دائماً من الخصم** (أدوات تشغيل المنصة نفسها، مثل الإعلان الجماعي، لا
تُحتسب استهلاكاً). الرد الآلي ورموز تحقق واتساب (OTP) لا يُخصَم عليهما شيء أبداً - هذا
تسعير لحملات/API المستخدمين فقط.

شحن المحفظة (من الإعدادات ← المحفظة، لأي مستخدم): يدوي (أي طريقة يضيفها الأدمن، مثل
بطاقات Super Key - يرفع صورة إثبات الدفع وينتظر موافقة الأدمن من "طلبات الشحن")،
Binance Pay (رقم عملية فعلي يتحقق منه الخادم تلقائياً عبر Binance API، يتحوّل للدينار
بسعر الصرف المضبوط بإعدادات الموقع)، وآسياسيل (تحويل رصيد هاتفي حقيقي برمزي تحقق SMS
متتاليين، يحوَّل تلقائياً لرصيد محفظة بنسبة خصم يحددها الأدمن).

## روابط لوحة الأدمن (مباشرة لكل قسم) مقابل تطبيق المستخدم العادي (/app فقط)

المستخدم العادي يبقى دائماً على الرابط `/app` بصرف النظر عن القسم الذي يتصفحه (الرابط
بالمتصفح لا يتغيّر إطلاقاً عند التنقل). الأدمن وحده يحصل على رابط مباشر قابل للمشاركة/
التحديث لكل قسم: `/app/wallet`، `/app/admin` (المستخدمين)، `/app/admin/security`،
`/app/admin/payments`، `/app/admin/recharge`، `/app/admin/site`... إلخ - هذا للتسهيل
فقط (تصفّح/مشاركة رابط)، والحماية الحقيقية تبقى من الخادم: أي مستخدم عادي يفتح رابط
أدمن مباشرة يُعاد فوراً لـ `/app` بلا رؤية أي محتوى (وكل استدعاءات API الفعلية محمية بـ
`require_admin()` بغض النظر عن أي رابط).

## التثبيت - موقع PHP

1. ارفع كل الملفات أعلاه (ما عدا `wasel-gateway/`) إلى `public_html` (أو مجلد الدومين).
2. أنشئ قاعدة MySQL ومستخدماً لها بكل الصلاحيات من لوحة الاستضافة (MySQL Databases) -
   **لا تستورد `sql/database.sql` يدوياً**، المثبّت بالخطوة التالية يسويها لك.
3. افتح `https://دومينك/install.php` بالمتصفح - صفحة تثبيت واحدة تطلب بيانات القاعدة
   (Host/اسم القاعدة/المستخدم/كلمة المرور) ودومينك وبريد+كلمة مرور حسابك كأدمن. تختبر
   الاتصال بالقاعدة، تنشئ كل الجداول، وتكتب `core/config.php` تلقائياً (بمفتاح سرّي
   عشوائي) - بدون تعديل أي ملف يدوياً. بعد الإرسال تُحوَّل لصفحة تسجيل الدخول وتدخل مباشرة
   بالبريد وكلمة المرور اللي كتبتهم.
   (ترفض هذه الصفحة العمل من نفسها لو `core/config.php` موجود فعلاً - ما تقدر تُستخدم
   لتخريب موقع شغّال، فقط للتثبيت الأول.)
4. بعد الدخول، من حسابي ← الإعدادات، اضبط `GATEWAY_BASE_URL`/`GATEWAY_TOKEN` بنفس قيم
   بوابة واتساب (أدناه) داخل `core/config.php` (يدوياً بعد التثبيت - المثبّت يكتب لك
   `GATEWAY_TOKEN` عشوائياً جاهزاً، بس `GATEWAY_BASE_URL` يحتاج رابط بوابتك الفعلي).
5. (اختياري) `GOOGLE_CLIENT_ID` بنفس الملف لتفعيل زر «الدخول بجوجل» - من Google Cloud
   Console ← APIs & Services ← Credentials ← Create OAuth client ID (Web application).

**إذا تفضّل التعديل اليدوي** (أو تعذّر على المثبّت كتابة الملف لمشكلة صلاحيات): انسخ
`core/config.sample.php` إلى `core/config.php` واكتب بياناتك، واستورد `sql/database.sql`
من phpMyAdmin (Import) أو `php tools/init_db.php`.

**تسجيل الدخول بعد التثبيت:** زر «دخول بالبريد الإلكتروني» بصفحة الدخول الرئيسية -
هذا هو المنفذ الوحيد الشغّال فوراً بعد التثبيت (قبل ربط أي حساب واتساب أو ضبط جوجل).
بعد ما تربط أول حساب واتساب وتفعّله كـ«مرسل الأكواد» من لوحة الأدمن، يصير تسجيل الدخول
برقم واتساب متاحاً لكل المستخدمين الجدد.

## التثبيت - بوابة واتساب (DirectAdmin ← Setup Node.js App)

1. ارفع مجلد `wasel-gateway/` إلى الاستضافة (أي مكان، مثلاً `domains/YOUR_DOMAIN/public_html/wasel-gateway`
   أو مجلد خارج public_html إذا تگدر - ما يحتاج يكون ظاهر من الويب أصلاً إلا على رابط فرعي).
2. **DirectAdmin ← Extra/Advanced Features ← Setup Node.js App ← Create Application:**
   - **Node.js version:** 20 أو أحدث
   - **Application root:** مسار مجلد `wasel-gateway` اللي رفعته (مثلاً `domains/YOUR_DOMAIN/public_html/wasel-gateway`)
   - **Application URL:** رابط فرعي تختاره (مثلاً `YOUR_DOMAIN/wasel-gw`)
   - **Application startup file:** `app.js`
   - اضغط **Create**.
3. من نفس صفحة التطبيق، أضف **Environment Variables:**
   - `GATEWAY_TOKEN` = نص عشوائي طويل وسرّي (نفس القيمة بالضبط تكتبها بـ `core/config.php` ← `GATEWAY_TOKEN`)
   - `WEBHOOK_URL` = `https://YOUR_DOMAIN/webhook/wa_incoming` (رابط موقعك + هذا المسار بالضبط - يفيد للرد الآلي فقط)
4. اضغط **Run NPM Install**، وبعد ما يخلص اضغط **Restart**.
5. ارجع للوحة تحكم DirectAdmin الرئيسية ← الصق رابط التطبيق (`https://YOUR_DOMAIN/wasel-gw`) ← حفظ واختبار ← لازم يطلع «شغّالة» (الصفحة ترجع `{"ok":true,"service":"wasel-gateway"}`).
6. بموقع PHP، `core/config.php`: اكتب `GATEWAY_BASE_URL` = نفس رابط التطبيق (`https://YOUR_DOMAIN/wasel-gw`)
   و`GATEWAY_TOKEN` = نفس القيمة اللي كتبتها بخطوة 3.

**إذا ما لقيت "Setup Node.js App" بلوحتك:** اطلب من شركة الاستضافة تفعّل **CloudLinux
Node.js Selector** - أغلب شركات الاستضافة المشتركة الحديثة تدعمه.

## الـ Cron (إلزامي - معالجة الحملات بالخلفية)

من لوحة الاستضافة ← **Advanced Features ← Cron Jobs** ← خلّي كل حقول الوقت `*` (أو
بالتحديد: كل دقيقة) ← الصق هذا الأمر (عدّل المسار لمسار موقعك الفعلي):

```
* * * * * php /home/USER/public_html/cron.php >/dev/null 2>&1
```

هذا السكربت يبقى شغال قريب من دقيقة كاملة بكل تشغيلة (قفل يمنع تشغيلتين بنفس الوقت)،
يرسل رسائل الحملات الجارية بالفاصل الزمني المحدد لكل حملة، وينظّف رموز التحقق المنتهية.
بدون هذا الـ Cron: الحملات تُنشأ لكنها **ما ترسل أي رسالة أبداً**.

## ربط أول حساب واتساب (بعد التثبيت)

1. من داخل الموقع: حسابي ← + إضافة حساب واتساب.
2. تفتح ورقة فيها رمز QR - امسحه من واتساب بجوالك (الأجهزة المرتبطة ← ربط جهاز).
3. بعد المسح يصير الحساب «متصل» تلقائياً (البوابة تتعرف على الاتصال من نفسها، بدون أي
   إعادة تحميل يدوية).
4. من لوحة الأدمن، فعّل حساباً واحداً كـ«مرسل الأكواد» (otp_sender) حتى يصير تسجيل الدخول
   بواتساب (الرمز المرسل للمستخدمين الجدد) شغّالاً.

## جاهز ومُختبَر فعلياً (تشغيل حقيقي: خادم PHP + MySQL + بوابة حقيقية، لا محاكاة)

* قاعدة بيانات MySQL كاملة (13 جدولاً) + تثبيت بخطوات واضحة + صفحات خطأ عربية تشرح أي
  مشكلة إعداد بالضبط (بدل صفحة بيضاء).
* تسجيل الدخول: واتساب برمز تحقق (الطريقة الرئيسية)، جوجل، بريد+كلمة مرور (احتياطي قديم)،
  حساب مدير ثابت اختياري. جلسة موقّعة بكوكي متوافق حرفياً مع Flask (نفس `SECRET_KEY` =
  يبقى المستخدمون مسجّلين الدخول بعد النقل من بايثون)، مدتها 30 يوماً.
* حسابات واتساب: ربط/فصل عبر QR حقيقي (Baileys، بدون متصفح)، حالة اتصال حية.
* الحملات: نص + أرقام + فاصل زمني، إيقاف مؤقت/استئناف/إلغاء نهائي/استثناء رقم، إرسال
  فعلي بالخلفية عبر Cron، إشعارات اكتمال.
* الرد الآلي: قواعد كلمة مفتاحية ← رد، عبر webhook فوري من البوابة عند استلام رسالة.
* المشتركين (CRM): إضافة/تجديد/حذف، رسالة بدء تلقائية، تذكير/انتهاء تلقائي (Cron).
* مفاتيح API خارجية (`/api/v1/send`) لإرسال رموز OTP من موقع خارجي - تتطلب اشتراك مفعّل
  وحساباً متصلاً، تتوقف تلقائياً إذا انفصل الحساب (بدون أي تعديل يدوي)، حد ٢٠ طلب/دقيقة.
* لوحة أدمن: العملاء + تفعيل/إيقاف الاشتراك (مع عرض الرصيد وفترة التجربة/الاشتراك لكل
  مستخدم)، إعدادات الموقع (بالكامل عبر نموذج حقيقي، بما فيها تسعير الرسالة وسعر صرف
  الدولار)، إعلان جماعي لكل المستخدمين، **مركز أمان** (فحوص حقيقية: قوة SECRET_KEY/
  GATEWAY_TOKEN، HTTPS، صلاحيات config.php، تشغيل الكرون، سجل تدقيق كل عمليات الأدمن،
  زر "إلغاء كل الجلسات" يتطلب كلمة المرور)، **طرق الدفع** (Binance/آسياسيل/يدوية بشعار
  مرفوع لكل طريقة)، **طلبات الشحن** (قبول/رفض بحماية من الشحن المزدوج).
* المحفظة: تسعير اختياري بالرسالة (معطّل افتراضياً)، شحن يدوي/Binance Pay (تحقق تلقائي
  حقيقي عبر Binance API)/آسياسيل (تحويل رصيد هاتفي حقيقي بخطوتي SMS)، الأدمن معفى دائماً.
* PWA: يمكن تثبيت واصل كتطبيق من المتصفح (`manifest.json` ديناميكي بالاسم/الألوان،
  Service Worker شبكة-أولاً بلا تخزين مؤقت للبيانات، أيقونة مولَّدة).
* انتقال بصري ناعم (تلاشي+انزلاق) بصفحة الدخول قبل تسجيل الدخول وبين خطواتها.
* روابط مباشرة لكل قسم بلوحة الأدمن (قابلة للمشاركة/التحديث)، بينما المستخدم العادي
  يبقى دائماً على `/app` - كل الصفحات السابقة "البطاقة المنبثقة" (الرد الآلي/المشتركين/
  مفاتيح API/لوحة الأدمن) صارت صفحات كاملة مصمَّمة، لا نوافذ منبثقة.
* حماية: CSRF، bcrypt، إيقاف تخمين كلمة المرور/الرموز، سجل تدقيق، ترويسات أمان، حماية
  SQL injection (استعلامات مُجهّزة فقط)، التوكن بين PHP والبوابة سرّي ومطلوب بكل طلب.
* واجهة فعلية (`/` دخول، `/app` تطبيق بتصميم بطاقات/منيو سفلي + صفحات أدمن مباشرة) -
  فُحصت بمتصفح حقيقي (Playwright/Chromium headless): تسجيل دخول (أدمن ومستخدم عادي)، كل
  الأقسام الجديدة والقديمة، الروابط المباشرة للأدمن، منع المستخدم العادي من رؤية صفحات
  الأدمن، الانتقال البصري، تسجيل الخروج.

## الناقص حالياً (جولة قادمة)

* رفع ملف Excel للأرقام، وإرفاق صورة/وسائط بالرسالة (الحملات نص فقط حالياً - البوابة ما
  تدعم إرسال صور بعد).
* جدولة حملة لوقت لاحق (send_at).
* استيراد/تصدير بيانات الموقع كـ JSON عبر بوت تلغرام - لم يُبنَ بعد هذه الجولة: التصدير
  وحده (نسخة احتياطية تُرسَل لبوت تلغرام) مخاطرته منخفضة وممكن إضافته بسهولة لاحقاً، لكن
  **الاستيراد** (الكتابة فوق بيانات حيّة من ملف خارجي) يحتاج تصميماً أكثر حذراً (تحقق من
  التوافق، نسخة احتياطية تلقائية قبل الاستيراد، صلاحية مشددة) فضّلت عدم المجازفة به بدون
  وقت كافٍ لاختباره فعلياً بدل تسليمه ناقص الاختبار.
* "Super Key" أُضيفت كطريقة دفع **يدوية** (قالب جاهز بزر "➕ أضف Super Key" بصفحة طرق
  الدفع) تحتاج موافقة الأدمن لكل عملية، وليست بتكامل API تلقائي - لا يوجد توثيق API رسمي
  أو معروف لهذه الخدمة بالمرجع الذي اعتمدته، فتجنّبت اختلاق تكامل لا أستطيع التأكد من
  صحته. لو عندك توثيق API فعلي لها أقدر أربطها تلقائياً مثل Binance/آسياسيل.
* أداة نقل بيانات حقيقية من قاعدة SQLite القديمة (migrate_from_sqlite).
* **تنبيه صدق (بروتوكولات خارجية حقيقية غير مُختبَرة ضد خدمات حية فعلياً بهذه البيئة):**
  - Baileys (الاتصال الفعلي بواتساب): ما فيه جوال لمسح QR بالبيئة المعزولة اللي بُني
    فيها الكود - أول ربط حقيقي لحساب هو أول اختبار فعلي لهذا الجزء.
  - Binance Pay API وآسياسيل API: الكود منقول بأمانة من مرجع يستعملهما فعلياً، وتحقّقت
    من كل مسارات الفشل المتوقعة (مفاتيح ناقصة، صيغة رقم خاطئة، مبلغ خارج الشرائح...) -
    لكن الاستدعاء الفعلي للخدمتين الخارجيتين (Binance/آسياسيل أنفسهما) لم يُجرَّب ضد
    حساب حقيقي بهذه الجلسة (قيود شبكة/سياسة على بيئة الاختبار). أول محاولة شحن حقيقية
    منك هي أول اختبار فعلي لهذا الجزء بالذات.
  - كل شي آخر (HTTP API، قاعدة البيانات، المحفظة، التوثيق، معالجة الأخطاء، الواجهة) مُختبَر
    فعلياً: خادم PHP حقيقي + MySQL حقيقي + 35 فحصاً تلقائياً عبر curl + بوابة واتساب
    مزيّفة بنفس البروتوكول + Playwright/Chromium حقيقي للواجهة.
