# Almulla - نسخة MySQL

هذا المشروع هو نفس تطبيق الكتالوج (الفئات/الشركات/المنتجات/الخدمات) الذي كان يعمل بملف واحد (`index_2.php`)
ويخزّن بياناته في ملف `logs/database.json`، بعد إعادة هيكلته ليعمل على **قاعدة بيانات MySQL** حقيقية،
مع فصل التنسيقات والسكربتات في ملفات مستقلة وإصلاح عدة مشاكل موجودة في الكود الأصلي.

## هيكل المشروع

```
index.php              نقطة الدخول (الجلسة، التوجيه، عرض الصفحة)
install.php            معالج التنصيب (إنشاء الجداول + استيراد البيانات القديمة + حساب المدير)
config.sample.php      قالب إعدادات الاتصال بقاعدة البيانات (ينشئه install.php تلقائياً باسم config.php)
install/schema.sql     بنية جداول قاعدة البيانات
includes/db.php        الاتصال بقاعدة البيانات (PDO)
includes/functions.php دوال المصادقة/CSRF/رفع الصور/السجلات
includes/data.php      كل عمليات القراءة/الكتابة على قاعدة البيانات
includes/api.php       نقاط الـ API (نفس الأسماء المستخدمة سابقاً في الواجهة الأمامية)
assets/css/style.css   كل تنسيقات الموقع (كانت مضمّنة داخل الصفحة)
assets/js/app.js       كل سكربت الموقع (كان مضمّناً داخل الصفحة)
uploads/               صور المنتجات/الشركات/الفئات المرفوعة
logs/                  سجلات التطبيق، وموضع ملف database.json القديم إن وُجد (لأغراض الاستيراد فقط)
```

## خطوات التنصيب على السيرفر

1. ارفع كل محتويات هذا المجلد إلى مجلد الموقع على الاستضافة.
2. إن كان لديك موقع سابق ببيانات فعلية: انسخ ملف `logs/database.json` القديم إلى مجلد `logs/` هنا،
   وانسخ محتويات مجلد `uploads/` القديم إلى مجلد `uploads/` هنا (الصور تبقى كما هي، لا حاجة لتعديلها).
3. أنشئ قاعدة بيانات MySQL فارغة ومستخدماً له كل الصلاحيات عليها (من لوحة تحكم الاستضافة).
4. افتح `https://your-domain.com/install.php` من المتصفح واتبع الخطوات:
   - أدخل بيانات الاتصال بقاعدة البيانات.
   - إذا ظهر لك خيار "استيراد البيانات الحالية" فعّله لنقل بياناتك القديمة تلقائياً.
   - أدخل بيانات حساب المدير الذي تريد الدخول به.
   - اضغط "بدء التنصيب".
5. بعد ظهور رسالة النجاح: **احذف `install.php` ومجلد `install/` من السيرفر فوراً** لأسباب أمنية.
6. سجّل الدخول من الصفحة الرئيسية بحساب المدير.

> ملاحظة: إن لم يكن لديك بيانات قديمة، يمكنك تجاهل خطوة الاستيراد وسيبدأ الموقع بكتالوج فارغ وحساب المدير
> الذي أدخلته في نموذج التنصيب فقط (لن يتم إنشاء الحسابات التجريبية الافتراضية القديمة).

## أهم ما تغيّر

- **قاعدة البيانات**: كل البيانات (المستخدمون، الفئات، الشركات، المنتجات، الخدمات، الإعدادات،
  الإحصائيات، الأكثر طلباً) أصبحت في جداول MySQL حقيقية بدلاً من ملف JSON واحد يُعاد كتابته بالكامل
  في كل عملية.
- **فصل CSS/JS**: التنسيقات في `assets/css/style.css` والسكربت في `assets/js/app.js` بدلاً من كونها
  مضمّنة داخل الصفحة. سلوك الواجهة لم يتغيّر إطلاقاً.
- **إصلاحات لمشاكل حقيقية كانت موجودة**:
  - **حذف الحساب الذاتي لم يكن يعمل أبداً**: كانت الواجهة تستدعي نقطة `verify_password` غير
    الموجودة أصلاً في السيرفر قبل حذف الحساب، فكانت تفشل دائماً برسالة "كلمة المرور غير صحيحة"
    حتى لو كانت صحيحة. تمت إضافة هذه النقطة وأصبح حذف الحساب يعمل.
  - **حذف عنصر من "الأكثر طلباً" وإخفاء/إظهار بطاقته** كانا يستدعيان نقطتين غير موجودتين في
    السيرفر (`delete_most_requested`, `toggle_hide_most_requested`)، فكانا يفشلان دائماً. تمت إضافتهما.
  - **ثغرة CSRF**: كانت أي صفحة خارجية قادرة (أثناء تسجيل دخول المدير) على تنفيذ عمليات تغييرية
    مثل مسح الكتالوج بالكامل عبر مجرد تحميل رابط أو صورة. أصبح كل طلب تغييري يتطلب رمز CSRF صحيحاً
    ويُقبل فقط بطريقة POST.
  - **الاعتماد على ترتيب العناصر (index) بدلاً من معرّفها الثابت (id)** في إخفاء/استعادة/تبديل حالة
    المنتجات والخدمات، وهو ما قد يصيب عنصراً خاطئاً إذا تغيّر ترتيب القائمة. أصبحت كل هذه العمليات
    تعتمد على المعرّف الثابت لكل عنصر.
  - **رفع الصور**: كان بالإمكان نظرياً حفظ ملف بامتداد غير آمن عبر التلاعب بترويسة base64. أصبح
    يُسمح فقط بامتدادات صور حقيقية (jpg/png/gif/webp) بعد التحقق من محتوى الملف فعلياً.
  - **حذف الصور**: كان اسم الملف المطلوب حذفه غير مُتحقق منه، ما يسمح نظرياً بمحاولة حذف ملفات
    خارج مجلد `uploads`. أصبح يُرفض أي اسم يحتوي على مسار.
  - **حماية مجلدي `uploads/` و `logs/`**: أضيفت ملفات `.htaccess` لمنع تنفيذ أي سكربت داخل مجلد
    الصور، ومنع الوصول المباشر لمجلد السجلات وملف قاعدة البيانات القديم.
  - كلمات مرور الحسابات التجريبية الافتراضية (`admin123`, `123456`) لم تعد مضمّنة في الكود؛ يُحدَّد
    حساب المدير الآن عبر نموذج التنصيب.

## متطلبات السيرفر

- PHP 7.4 أو أحدث (تم تطويره واختباره على PHP 8.4) مع امتداد `pdo_mysql`.
- قاعدة بيانات MySQL 5.7+ أو MariaDB 10.2+.
