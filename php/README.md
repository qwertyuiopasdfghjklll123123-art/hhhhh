# fastcrand — نسخة PHP + MySQL (نقل أمين من نسخة بايثون)

هذا المجلد هو **نفس الموقع** الذي كان مكتوباً بـ Python/Flask/SQLite، لكن بنظام خلفي جديد: **PHP + MySQL**.
واجهة الموقع (HTML/CSS/JS) مستخرجة من `app.py` الأصلي ثم **حُدِّثت عمداً** في أجزاء محددة (انظر «الميزات الجديدة»: التصميم المسطّح، الأمان والجلسات، الألعاب، الشعار المتحرك)، وكل مسارات الموقع والـ API الأصلية (182 قاعدة Flask / 174 عنواناً) باقية بنفس العناوين ونفس شكل الطلب ونفس الـ JSON، وأُضيفت مسارات جديدة فقط.
الإضافات الجديدة: **رابط مستقل لكل قسم** بلوحة الإدارة، وقسم **استيراد وتصدير** (نسخ تلغرام)، و**مركز أمان** وحماية شاملة للوحة الأدمن، وتثبيت **بملف SQL + ملف إعدادات** بدل المثبّت، و**المصادقة الثنائية (2FA)** و**الأجهزة والجلسات**، و**خدمات الألعاب** (شحن ببجي وغيره) مع محادثة الإدارة، وتصميم مسطّح جديد للأزرار والبطاقات، و**شعار متحرك** يرفعه الأدمن بدل اسم الموقع (انظر «الميزات الجديدة» أدناه).

```
(جذر الموقع: public_html أو مجلد الدومين — الملفات تظهر هنا مباشرة عند فك الأرشيف)
├─ .htaccess          ← يوجّه الطلبات إلى public/ ويحجب المجلدات الخاصة (يلزم فقط حين يكون جذر الموقع هو مجلد الأرشيف نفسه)
├─ public/            ← نقطة الدخول: index.php + .htaccess
├─ core/
│  ├─ config.php      ← الملف الوحيد الذي تعدّله (بيانات القاعدة + حساب الأدمن)
│  ├─ bootstrap.php   ← تهيئة، تحميل المكتبات والمسارات، صفحات الإعداد الواضحة
│  ├─ lib/            ← قاعدة البيانات، الجلسات، الحماية (security.php)، الاستيراد (transfer.php)، SMTP، Web Push، المهام...
│  ├─ routes/         ← كل مسارات الموقع (مقابل @app.route بـ app.py) + transfer.php + security.php
│  └─ templates/      ← الواجهات الأصلية + dash_router.js (روابط الأقسام) + dash_admin_tools.js (صفحتا الاستيراد والأمان)
├─ sql/database.sql   ← قاعدة البيانات كاملة في ملف واحد (26 جدولاً + البيانات الافتراضية) — يُستورد من phpMyAdmin
├─ cron.php           ← المهام الدورية (بديل threads بايثون)
├─ tools/             ← init_db.php، create_admin.php، migrate_from_sqlite.php
└─ data/              ← يكتب فيه الموقع (صور/صوتيات/نسخ احتياطية/كاش/سجلات) — لا يُخدَم من الويب
```

> مجلد الشيفرة اسمه `core` (وليس `app`) عمداً: `/app` هو رابط لوحة المستخدم في الموقع، ومجلد بنفس الاسم كان سيتعارض معه على Apache.

## الميزات الجديدة (واجهة المستخدم)

### المصادقة الثنائية (2FA) والأجهزة والجلسات — «حسابي ← الأمان»
* **2FA** بتطبيق مصادقة (Google Authenticator / Authy / Microsoft Authenticator): امسح رمز QR أو أدخل المفتاح يدوياً ثم اكتب رمز 6 أرقام. تحصل على **8 رموز احتياطية** (تُعرض مرة واحدة؛ كل رمز يعمل مرة واحدة). بعد التفعيل يطلب الموقع الرمز عند كل تسجيل دخول (كلمة المرور أو Google)، وحسابات 2FA **لا تُسجَّل تلقائياً** بعد استعادة كلمة المرور. إيقاف 2FA أو توليد رموز جديدة يتطلب كلمة المرور + رمزاً. الرمز لا يُقبل مرتين، وتخمينه محدود (يُحظر بعد عدة محاولات خاطئة).
* **الأجهزة والجلسات:** كل تسجيل دخول يظهر في قائمة (الجهاز/المتصفح، العنوان، آخر نشاط) مع بطاقة خضراء للجهاز الحالي، وزر «إنهاء» لأي جهاز وزر «إنهاء كل الجلسات الأخرى». الجلسة المُنهاة تُخرَج في طلبها التالي. (جدول `user_sessions`؛ لا يدخل في النسخ الاحتياطي.)
* سرّ 2FA يُخزَّن **مشفّراً** (AES-256-GCM بمفتاح مشتق من `SECRET_KEY`) فلا تكفي قاعدة بيانات أو نسخة احتياطية مسرّبة وحدها. **تغيير `SECRET_KEY` يُبطل 2FA** لمن فعّلها؛ لمن فقد هاتفه ورموزه أو بعد تغيير المفتاح: `php tools/disable_2fa.php email@example.com`.
* القواعد المستوردة من إصدار أقدم تُرقّى تلقائياً (أعمدة `totp_*` وجدول الجلسات) عند أول زيارة.

### خدمات الألعاب (شحن ببجي وغيره)
* من لوحة الأدمن ← **الخدمات المخصصة ← إضافة**: اختر النوع **لعبة**، اكتب اسمها وباقاتها وأسعارها (مثل `325 UC` = `4.99`) وصورة اختيارية.
* تظهر في الرئيسية كشريط **قابل للسحب يميناً ويساراً** مع «عرض الكل». العميل يكتب **معرّف اللاعب (ID)** ويختار الباقة فيرى رصيده بعد الخصم؛ عند الطلب **يُخصم المبلغ ويُفتح محادثة مع الإدارة** (تذكرة مرتبطة بالطلب). تغيير الأدمن لحالة الطلب (قيد التنفيذ/مكتمل/ملغي مع استرجاع) يُكتب داخل المحادثة نفسها.
* الطلبات المخصّصة تظهر في **طلباتي** (تبويب «الألعاب») مع زر «فتح المحادثة» ونقطة حمراء عند ردّ جديد من الإدارة.

### الشعار المتحرك
* لوحة الأدمن ← **اللوغو واسم الموقع ← شعار متحرك**: ارفع فيديو **webm بخلفية شفافة** أو صورة متحركة (**gif / webp / png / svg**) حتى 8MB، فيظهر للمستخدمين في الشريط العلوي **بدل اسم الموقع**. لشفافية الفيديو على Safari/iOS ارفع أيضاً نسخة **mov** (HEVC بقناة ألفا). الملفات تُفحص بمحتواها (لا تُقبل سكربتات)، وتُخدَّم بترويسة تمنع تنفيذها.

### مظهر جديد
أزرار بأحجام (30/36/44/54) وأنماط مسطّحة (رئيسي/ثانوي/إطار/نجاح/خطر)، أيقونات المنصات أكبر ولامعة، شعار طريقة الدفع يظهر في الشحن إن رفعتَه، المساعد الذكي ببطاقة واضحة، «المزيد من الإعدادات» قابلة للطي في حسابي، وتحسين صفحتي طلباتي والشحن. **المستخدم العادي يرى `/app` فقط** دون أسماء أقسام بعده (روابط الأقسام للأدمن).

**لوحة الأدمن بلا قائمة جانبية:** الأدمن يرى نفس **المنيو السفلي** للمستخدم (الرئيسية / طلباتي / الشحن / حسابي)، وكل أقسام القائمة الجانبية القديمة (طلبات الشحن، تذاكر الدعم، طلبات SMM، الخدمات المخصصة، المستويات، الاستيراد والتصدير، مركز الأمان…) صارت داخل **حسابي**. أحجام المنيو والصفوف والأيقونات مأخوذة من الصورة المرجعية بتصميم مسطّح.

**الرئيسية والحساب (تحديث):** الرئيسية فيها شريط واحد «الألعاب» تظهر ضمنه الخدمات المخصصة أيضاً (يتحرك تلقائياً بهدوء)، و«عرض الكل» يفتح الألعاب والمخصصة معاً. الشريط العلوي فيه شارة الرصيد (تفتح الشحن) والإشعارات. في «حسابي»: إحصائيات تفاعلية (اضغط أي بطاقة للانتقال لقسمها + شريط توزيع الطلبات)، **«المزيد من الإعدادات»** تفتح صفحة خاصة فيها **زر اللغة (عربي/English)** والمظهر والإشعارات والعملة والمكافآت والكوبون، وسياسة الخصوصية والشروط فوق زر الخروج. **التقييمات** صارت في «حسابي» بلا بطاقة (كتابة + مشاهدة + **إعجاب ♥**) وصفحة «كل التقييمات» مع الترقيم. واجهة إنشاء الطلب أُعيد ترتيبها (كميات سريعة + المجموع + رصيدك بعد الطلب). **بعد اكتمال/إلغاء طلب لعبة أو خدمة مخصصة تُقفل محادثته على العميل** (وتُفتح لو رجع الطلب «قيد التنفيذ»). ترجمة الإنكليزية تغطي الواجهات الرئيسية للمستخدم (أما لوحة الإدارة والنصوص الطويلة كالسياسات فتبقى بالعربية). الإعجابات تُخزَّن في عمودين جديدين بجدول reviews (`likes`, `liked_by`) يُضافان تلقائياً للقواعد القديمة.

**تحديث الواجهة (٣):** صفحة «المزيد من الإعدادات» صارت تضم: الحساب (إعدادات الحساب، سجل المعاملات، API)، الدعم (إنشاء تذكرة، تذاكري، الأسئلة الشائعة)، آراء العملاء، اللغة والمظهر والإشعارات والعملة والكوبون. «حسابي» صارت أخف: بطاقة المستخدم + 3 إحصائيات (الرصيد، الإنفاق، المكتملة) + **بطاقة المطوّر** + الأمان. **بطاقة المطوّر** صغيرة بحركة هادئة، تفتح واتساب المطوّر عند الضغط، وتحدّد الأدمن اسمها وصورتها ورقمها من «الإعدادات ← بطاقة المطوّر» (تختفي عن المستخدمين إن لم يُكتب رقم). بطاقة الترحيب بتصميم هندسي جديد، وزر الإشعارات أكبر ودائري، وصفحة الإشعارات مرتّبة (ملخص + تبويبات + تجميع بالتاريخ + حذف مفرد). صفحة الشحن: بطاقات طرق الدفع بحركات دخول، مقسّمة إلى «دفع تلقائي» و«تحويل يدوي». أُزيلت عبارة «تسليم يدوي» من واجهة الألعاب.

**تحديث الواجهة (٤):** صفحة الدخول قبل التسجيل بلا بطاقة دخول: زر **«ابدأ الآن»** يفتح صفحة تسجيل الدخول/إنشاء الحساب. طرق الدفع **شريط واحد** (صف تحت صف) بلا تقسيم تلقائي/يدوي، وكل صفحات الدفع (آسياسيل، باينانس، نجوم تليجرام، اليدوي) بشكل موحّد: ترويسة + خطوات مرقّمة + أقسام مرقّمة. تفعيل الإشعارات **ورقة منبثقة من الأسفل** (تُغلق بالسحب). بطاقة الترحيب بنصف الحجم، وبطاقات الإشعارات أصغر. **سرعة التحميل:** الطلبات والإشعارات وطرق الدفع تظهر فوراً من آخر نسخة محفوظة بالمتصفح (لكل مستخدم، وتُمسح عند الخروج) ثم تتحدّث بالخلفية، مع تحميل مسبق وهياكل تحميل، والطلبان (سمم + مخصص) يُجلبان بالتوازي. **حالات فارغة مصوّرة** (طلبات، إشعارات، تذاكر، معاملات، تقييمات، مفضلة، طرق دفع). صفحة المستويات والمكافآت بتصميم جديد (بطاقة المستوى + مزايا + سلّم زمني). **الأدمن يرى كل ما يراه المستخدم** (المساعد الذكي، الكوبون، الدعم، إعدادات الحساب…).

**تحديث الواجهة (٥):** صفحة الدخول بلا شريط علوي، وتسجيل الدخول/إنشاء الحساب **صفحة كاملة الشاشة** (ترويسة بالشعار + حقول كبيرة + أزرار). صفحات آسياسيل وباينانس والنجوم والتحويل اليدوي: مبالغ بخط كبير وأزرار مبالغ سريعة وبطاقات أرقام للشرائح وحقول رموز بحجم كبير وأزرار دفع بارزة. صفحة الألعاب والخدمات المخصصة وصفحة المفضلة (مجمّعة حسب المنصة) وصفحات حسابي الفرعية (إعدادات الحساب، سجل المعاملات، API، التذاكر، الأسئلة الشائعة، الكوبون) بتصميم موحّد. **ملاحظة:** خاصية «العمل دون اتصال» أُزيلت بالكامل؛ الـ Service Worker يكتفي بكاش الصور والخطوط والملفات الثابتة وإشعارات Push، والصفحات وواجهات البيانات تُجلب دائماً من الإنترنت (ويُنظَّف كاش الإصدارات القديمة تلقائياً). **كاش الصور:** الصور والشعارات (شعار الموقع، طرق الدفع، الأفاتار، صور التذاكر…) تُخزَّن بالمتصفح ولا تُحمَّل من جديد عند كل انتقال. **الشعار المتحرك الافتراضي:** شعار FC (من الصورة المرفقة) يتشكّل خلال 5 ثوانٍ في الشريط العلوي افتراضياً (SVG شفاف)، ويمكن للأدمن من «اللوغو واسم الموقع» أن يرفع شعاراً/فيديو خاصاً بدله، أو يختار «اسم الموقع فقط»، أو يعود للافتراضي، ويحمّل نسخة **webm شفافة** من الشعار الافتراضي (5 ثوانٍ) لإعادة استعمالها. أيقونة التطبيق الافتراضية صارت شعار FC نفسه، وبطاقة «ثبّت التطبيق» بتصميم جديد.

**لوغو للألعاب والخدمات المخصصة:** من «الخدمات المخصصة» ارفع لوغو (png/jpg/webp/gif حتى 2MB، يُفحص محتواه) عند إضافة اللعبة، أو غيّره لاحقاً من زر الصورة بجانب كل خدمة؛ يظهر في شريط الألعاب بالرئيسية و«عرض الكل» وصفحة الطلب، ويُحذف الملف القديم عند التغيير أو حذف الخدمة.

## التثبيت (3 خطوات، بلا مثبّت ويب)

### 1) ارفع الأرشيف وفكّه داخل `public_html`
ارفع `fastcrand_php.zip` إلى `public_html` (أو مجلد الدومين) ثم **Extract هناك مباشرة** — لا يوجد مجلد علوي، فتظهر `public/ core/ sql/ data/ tools/ cron.php .htaccess` داخل `public_html` نفسه.
(تأكد أن الملف المخفي `.htaccess` ظهر/نُسخ — فعّل «إظهار الملفات المخفية».) يجب أن يعمل الموقع على **جذر** دومين أو نطاق فرعي (`example.com` أو `shop.example.com`) لا داخل مجلد فرعي — كالنسخة الأصلية، فمساراته مطلقة (`/app` و`/api/...`).

### 2) أنشئ قاعدة بيانات واستورد `sql/database.sql`
1. من لوحة الاستضافة: **MySQL Databases** ← أنشئ قاعدة (مثلاً `user_fastcrand`) ومستخدماً لها بكلمة مرور، وأضف المستخدم إلى القاعدة بكل الصلاحيات (All Privileges).
2. افتح **phpMyAdmin** ← اختر القاعدة ← **Import (استيراد)** ← اختر الملف `sql/database.sql` ← **Go**.
   (الملف آمن عند التكرار: لا يمسح شيئاً ولا يكرر البيانات. ولا يحتوي أي مستخدم.)
3. بديل لمن لديه SSH: `mysql -u USER -p DBNAME < sql/database.sql` أو `php tools/init_db.php`.

### 3) عدّل `core/config.php` (الملف الوحيد)
افتحه بمحرر الملفات في لوحة الاستضافة واكتب:

```php
define('DB_HOST', 'localhost');          // غالباً localhost
define('DB_NAME', 'user_fastcrand');     // اسم القاعدة كما يظهر بلوحة الاستضافة
define('DB_USER', 'user_fastcrand');
define('DB_PASS', 'كلمة-مرور-القاعدة');
define('DOMAIN',  'example.com');        // دومينك بدون https://
define('ADMIN_EMAIL',    'me@example.com');   // بريدك
define('ADMIN_PASSWORD', 'كلمة-مرور-قوية');   // 8 محارف فأكثر
```
(`SECRET_KEY` مولَّد لك عشوائياً داخل الأرشيف — لا تغيّره بعد الإطلاق وإلا خرج كل المستخدمين.)

افتح موقعك: **تُنشأ حسابات الأدمن تلقائياً** من `ADMIN_EMAIL/ADMIN_PASSWORD` عند أول زيارة، ثم سجّل الدخول وادخل لوحة الإدارة. **بعد أول دخول احذف سطر `ADMIN_PASSWORD`** من الملف (لا يُستعمل بعد إنشاء الحساب أصلاً، ومركز الأمان ينبّهك إن بقي).

### 4) المهام الدورية (إلزامي)
من لوحة الاستضافة ← **Cron Jobs** ← كل دقيقة:

```cron
* * * * * php /home/USER/public_html/cron.php >/dev/null 2>&1
```
(إن لم يُعرف الأمر `php` فاكتب مساره الكامل، مثل `/usr/local/bin/php` أو `/opt/cpanel/ea-php83/root/usr/bin/php`.)
تشغّل الطلبات المعلّقة (كل 30ث)، فحص حالات الطلبات (5د)، مزامنة الأسعار (3د)، مزامنة/استيراد الخدمات، التعويض التلقائي (24س)، نسخ محلي (ساعة) وإلى تلغرام (6س)، تنظيف الصور (ساعة)، رسائل المساعد (6س).

### إن لم تعمل الصفحة بعد التثبيت
بدل صفحة بيضاء/خطأ 500، يعرض الموقع **صفحة عربية تقول ما الناقص بالضبط** (بلا أي سر):

| الرسالة | الحل |
|---|---|
| لم تُكتب بيانات قاعدة البيانات بعد | عدّل `DB_NAME/DB_USER/DB_PASS` في `core/config.php` |
| بيانات الدخول إلى قاعدة البيانات غير صحيحة | راجع `DB_USER/DB_PASS` وأضف المستخدم للقاعدة بكل الصلاحيات |
| قاعدة البيانات غير موجودة | راجع `DB_NAME` (غالباً يبدأ ببادئة حساب الاستضافة) |
| جداول الموقع غير موجودة | استورد `sql/database.sql` في القاعدة المحدّدة بـ `DB_NAME` |
| لا يوجد حساب أدمن بعد | اكتب `ADMIN_EMAIL/ADMIN_PASSWORD` في `core/config.php` ثم أعد تحميل الصفحة |

## استيراد وتصدير (نسخ تلغرام) — `/app/import-export`

**التصدير:** نسخة كاملة (ZIP = قاعدة البيانات + ملفات JSON، بنفس صيغة نسخ تلغرام)، أو **ملف JSON واحد شامل** (كل الجداول + ملفات VAPID والاشتراكات وكاش الخدمات داخل ملف `.json` واحد)، أو قاعدة البيانات فقط (SQL يُستورد أيضاً من phpMyAdmin)، أو ملفات JSON فقط (مفاتيح VAPID، اشتراكات الإشعارات، كاش الخدمات). يطلب كلمة مرور حسابك.

**الاستيراد:** ارفع الملف الذي وصلك من بوت تلغرام. المقبول:

| الملف | المصدر |
|---|---|
| `fastcrand_cloud_backup_*.zip` يحوي `fastcrand.sql` + JSON | نسخ هذا الموقع (PHP) |
| `fastcrand_cloud_backup_*.zip` يحوي `fastcrand.db` + JSON | نسخ موقع بايثون القديم (SQLite) — يحتاج امتداد `pdo_sqlite` |
| `fastcrand_db_*.json` (`"format":"fastcrand-db"`) | **ملف JSON واحد شامل** لكل الجداول + ملفات JSON الثلاثة (يُقبل أيضاً داخل ZIP باسم اختياري) |
| `.sql` | نسخة هذا الموقع أو تصدير phpMyAdmin/mysqldump |
| `.db` | قاعدة موقع بايثون مباشرة |
| `fc_vapid.json` · `fc_push_subs.json` · `fc_services_cache.json` | ملفات JSON منفردة |

الخطوات: ارفع الملف ← يُفحص ويُعرض ما بداخله (الجداول وعدد صفوفها) ← اختر ما تستعيده ← أدخل كلمة مرورك واكتب `RESTORE` ← ابدأ.
كما يمكنك **جلب النسخة مباشرة من تلغرام عبر البوت** (النسخ التي أرسلها هذا الموقع، حتى 20MB)، أو استعادة إحدى **النسخ المحفوظة على الخادم**.

**ضمانات السلامة:**
* لا يُنفَّذ أي أمر من الملف المرفوع سوى **صفوف INSERT بقيم حرفية** (لا CREATE/DROP/ALTER/UPDATE/GRANT ولا دوال ولا استعلامات فرعية)، وتُقبل جداول الموقع المعروفة فقط (25 جدولاً)؛ أي ملف يحوي غير ذلك يُرفض كاملاً. ملفات ZIP تُقرأ بأسماء معروفة فقط (بلا مسارات)، مع حدود ضد قنابل الضغط.
* تُحمَّل الصفوف في **جداول مؤقتة** ثم تُبدَّل بجملة `RENAME TABLE` واحدة **ذرّية**: إما ينجح كل شيء أو تبقى بياناتك كما هي. الجداول غير الموجودة في النسخة تبقى كما هي.
* **نسخة أمان تلقائية** (`backup_pre_import_*`) قبل أي تغيير، تُحفظ مع ملفات JSON القديمة، ويمكن استعادتها من نفس الصفحة.
* **وضع صيانة** مؤقت أثناء الاستيراد (ينتهي تلقائياً)، وقفل يمنع استيرادين معاً.
* يُرفض الاستيراد إن لم تحوِ النسخة أي أدمن (حتى لا تفقد الدخول).
* بعد الاستيراد **تُلغى كل الجلسات** (قد يختلف المستخدمون) فتسجّل الدخول من جديد (بحساب الأدمن الموجود في النسخة).

**صيغة JSON الشاملة** (`fastcrand-db`، الإصدار 1): `{"format":"fastcrand-db","version":1,"tables":{"users":{"columns":[...],"autoinc":N,"rows":[[...],...]},...},"files":{"fc_vapid.json":{...},"fc_push_subs.json":{...},"fc_services_cache.json":{...}}}` — تُطبَّق عليها نفس ضمانات السلامة (جداول معروفة فقط، تحميل مؤقت ثم تبديل ذرّي، نسخة أمان، رفض الاستيراد بلا أدمن)، والأعمدة غير الموجودة بالمخطط (مثل `md5_password` القديم) تُضاف تلقائياً فلا يضيع شيء. لتحويل نسخة بايثون القديمة إلى هذا الملف: `python3 tools/sqlite_to_dbjson.py <مجلد فيه fastcrand.db وملفات JSON> out.json`.

سطر الأوامر (لقواعد كبيرة أو بلا واجهة): `php tools/migrate_from_sqlite.php --sqlite=/path/fastcrand.db --files=/root [--truncate] [--dry-run]`.
يرفض الأمر الكتابة فوق بيانات موجودة (قبل أن يكتب أي شيء): إن زرت الموقع قبله فقد أُنشئ حساب الأدمن الجديد، فأضف `--truncate` ليحلّ محلّه حساب الأدمن القديم. (بيانات `sql/database.sql` الافتراضية — المستويات/طرق الدفع/المزوّد — لا تمنع النقل؛ يستبدلها بما عندك.)

## تحكم بالخدمات — `/app/services`

صفحة جديدة بديلة لـ«إدارة الخدمات» (الصفحة القديمة بقيت باسم `/app/services-advanced` للإخفاء/الاستعادة/حذف المنصات):
* **خدماتي:** كل خدمة معروضة بالمتجر مع تكلفتك وسعر البيع وشارات **♻ تعويض** و**✖ إلغاء** (تُكتشف تلقائياً من حقلي `refill` و`cancel` عند المزوّد) و**✎ معدّلة**؛ بحث وفلاتر (منصة، مزوّد، تعويض/إلغاء/معدّلة/مفقودة)، وتحديد متعدد لتغيير الربح أو الإخفاء أو إرجاع الأصل دفعة واحدة.
* **تعديل خدمة:** الاسم والوصف والفئة، والسعر إمّا **نسبة ربح %** أو **سعر ثابت $ لكل 1000** (يتجاوز النسبة) مع معاينة فورية لسعر المستخدم وربحك؛ تُطبَّق فوراً على المتجر وعلى `/api/v2`. ترك الحقل فارغاً = اسم/وصف/سعر المزوّد.
* **إضافة من مزوّد:** اختر المزوّد ← **مجموعة خدمات** (تحدّد فئات كاملة + نسبة ربح واحدة) أو **خدمة واحدة** (استيراد مع اسم/وصف/سعر مخصّص اختياري). خدمة بنفس الرقم والمنصة من مزوّد آخر لا تُستبدل بصمت.
* نقاط الـ API: `/api/admin/svc-ctl/{overview,provider,import,mine,update,bulk}` (أدمن فقط).

## التعويض والإلغاء بجانب الطلب

يقرأ الموقع تلقائياً حقلي `refill` و`cancel` لكل خدمة عند مزوّدها ويحفظهما مع الطلب؛ وبصفحة «طلباتي» يظهر **بجانب كل طلب**:
* زر **تعويض** للطلب المكتمل/الجزئي إن كانت الخدمة تدعمه (بعد 24 ساعة من الطلب، وبين تعويض وآخر 23 ساعة، وضمن مدة التعويض)، وإلا تظهر ملاحظة «التعويض بعد X ساعة».
* زر **إلغاء الطلب** للطلب النشط إن كانت الخدمة تدعم الإلغاء (`POST /api/cancel-order`): يُرسَل `cancel` للمزوّد ويُسترجع المبلغ تلقائياً فور تأكيد الإلغاء (أو عبر فحص الكرون). الطلب **المنتظر** (لم يصل للمزوّد لعدم كفاية رصيده) يُلغى محلياً دائماً مع استرجاع كامل.
* الطلبات القديمة التي لا تحمل العلم تُكتشف حيّاً من قائمة المزوّد.

## الانتقال من موقع بايثون الحالي
1. ثبّت النسخة الجديدة (الخطوات أعلاه) وسجّل دخولك كأدمن.
2. **عبر الموقع:** نزّل آخر ZIP من تلغرام (فيه `fastcrand.db` + JSON) وارفعه بقسم «استيراد وتصدير» — أو بالأمر `tools/migrate_from_sqlite.php`.
   يحافظ على المعرّفات وترتيب الصفوف وكلمات المرور ومفاتيح VAPID واشتراكات Web Push، وأي عمود موجود بقاعدتك القديمة وغير موجود بالمخطط يُضاف تلقائياً.
3. بعد الاستيراد تدخل بحساب الأدمن القديم. **للإبقاء على تسجيل دخول المستخدمين** ضع في `core/config.php` نفس `SECRET_KEY` المستعمل بموقع بايثون (كوكي الجلسة متوافق مع Flask) — لكنه معروف علناً، فالأفضل تغييره بعد استقرار النقل (سيُطلب من المستخدمين الدخول مرة واحدة).
4. أوقف خدمة بايثون ووجّه الدومين للنسخة الجديدة.

## الحماية (لوحة الأدمن والحسابات)
**تعمل تلقائياً بلا أي إعداد:**
* **كل مسارات `/api/admin/*` (107 مسار/طريقة) مختبَرة**: بلا جلسة أو بمستخدم عادي تُرفض كلها، والتحقق من الأدمن يتم من قاعدة البيانات في كل طلب (إلغاء صلاحية أدمن أو حظره يسري فوراً رغم أن الجلسة صالحة سنة).
* **حماية CSRF:** يُرفض أي طلب تعديل (POST/PUT/DELETE) قادم من موقع آخر للمتصفح المسجّل الدخول (فحص Origin/Referer)، ونقاط الاستيراد/التصدير/الأمان تطلب فوق ذلك رمزاً سرّياً بالجلسة وكلمة مرورك.
* **إيقاف التخمين:** الدخول (8 محاولات فاشلة لكل حساب+عنوان ثم إيقاف 15 دقيقة، دون أن يُقفَل صاحب الحساب الحقيقي من عنوانه)، ورمز التفعيل/استعادة كلمة المرور المكوّن من 6 أرقام (6 محاولات ثم يُبطَل الرمز)، وطلبات إرسال الرموز، والتسجيل الآلي.
  > كانت نسخة بايثون تسمح بتخمين رمز استعادة كلمة المرور بلا حد، فيمكن سرقة أي حساب (بما فيه الأدمن) خلال دقائق بمعرفة بريده. أُغلقت.
* **كلمات المرور:** كانت sha256 بلا ملح (تُكسَر بسرعة لو تسرّبت القاعدة أو نسخة تلغرام)؛ الآن **bcrypt** للجديد، وكلمات المرور القديمة تُرقّى تلقائياً وبصمت عند تسجيل دخول صاحبها. (للإبقاء على صيغة الأصل: `define('PASSWORD_HASH_UPGRADE', false);` — يلزم فقط إن أردت إمكانية الرجوع لنسخة بايثون.)
* **سجل تدقيق** لكل عملية تعديل بلوحة الإدارة (الوقت، العنوان، الحساب، المسار — بلا أجسام الطلبات) ولمحاولات CSRF والاستيراد/التصدير، يظهر في `/app/security` (وملفه `data/logs/admin_audit.log`).
* ترويسات أمان (`X-Frame-Options` `X-Content-Type-Options` `Referrer-Policy` و`HSTS` على HTTPS)، وكوكي الجلسة `HttpOnly` + `SameSite=Lax` (+`Secure` على HTTPS).
* **مركز الأمان `/app/security`:** يفحص حالة الحماية (مفتاح الجلسات، HTTPS، حسابات افتراضية معروفة، صيغة كلمات المرور، صلاحيات الملفات، النسخ الاحتياطي والكرون...)، ويختبر من الخادم نفسه أن ملف الإعدادات وقاعدة البيانات والسجلات **غير مكشوفة** من الويب، ويتيح **إلغاء كل الجلسات** فوراً.

**اختيارية في `core/config.php`** (انظر التعليقات داخله): `ADMIN_IP_ALLOWLIST` لتقييد لوحة الإدارة بعناوين/نطاقات معيّنة، `TRUSTED_PROXIES` إن كنت خلف Cloudflare/بروكسي (لقراءة عنوان الزائر الحقيقي بأمان)، وحدود المحاولات.

**قائمة تحقق قبل الإطلاق:** ✔ `SECRET_KEY` عشوائي وطويل (يولّده الأرشيف) ✔ احذف `ADMIN_PASSWORD` من config.php بعد أول دخول ✔ فعّل HTTPS ✔ شغّل «فحص تعرّض الملفات الخاصة» بمركز الأمان ✔ اضبط Bot Token بإعدادات النسخ الاحتياطي لتصلك نسخة خارج الخادم ✔ فكّر بـ `STRICT_PRICING` (أدناه).

**سعر الطلب:** `STRICT_PRICING` صار `true` افتراضياً في `config.sample.php` (التثبيتات الجديدة): الخادم يتحقق أن سعر كل طلب لا يقل عن سعر الكتالوج (بعد الأرباح والسعر الثابت وخصم المستوى)، فلا يستطيع مستخدم شراء خدمة بسعر 0. التثبيتات القديمة تحتفظ بقيمتها بـ `config.php` — مركز الأمان يخبرك إن كانت معطّلة.

## المهام الدورية بديل: خدمة دائمة
أو كخدمة دائمة بدل الكرون: `php cron.php --daemon`. أوامر مفيدة: `--list` (الجدول وآخر تشغيل)، `--job=queued` (تشغيل مهمة الآن)، `--once`. كل مهمة بعملية منفصلة وبقفل خاص بها. السجل: `data/logs/cron.log`.

```ini
# /etc/systemd/system/fastcrand-cron.service
[Service]
ExecStart=/usr/bin/php /path/to/cron.php --daemon
Restart=always
User=www-data
[Install]
WantedBy=multi-user.target
```

## إعداد الخادم

**Apache:** `.htaccess` (بجانب `core/`) و`public/.htaccess` جاهزان: الأول يوجّه كل شيء إلى `public/` ويحجب `core/ data/ sql/ tools/ tests/` و`cron.php`، والثاني يوجّه لـ index.php ويرفع حد الرفع إلى 64MB ويحوّل http→https بـ 301 كما كانت نسخة بايثون. فعّل `mod_rewrite` و`AllowOverride All`.

> **شهادة SSL:** يحوّل الموقع كل طلب `http://` إلى `https://` بـ 301 (يُسقط الـ query string؛ لا تحويل على localhost أو خلف بروكسي/CDN يرسل `X-Forwarded-Proto: https`). مسار `/.well-known/` (تحقق الشهادات) **مستثنى**. إن لم تكن لدومينك شهادة SSL بعد فعلّق قاعدة التحويل (5 أسطر في `.htaccess`، ومثلها في `public/.htaccess`) مؤقتاً.

**VPS:** الأفضل جعل DocumentRoot هو مجلد `public` نفسه (فتصبح `core` و`data` خارج الجذر)، وعندها `.htaccess` الذي بجانب `core/` غير مستعمل ولا يضر.

**Nginx + PHP-FPM:**
```nginx
server { listen 80; server_name example.com; return 301 https://$host$uri; }   # الأصل يُسقط الـ query أيضاً
server {
  listen 443 ssl http2; server_name example.com;
  root /var/www/fastcrand/public; index index.php;
  client_max_body_size 64m;
  location / { try_files $uri /index.php?$query_string; }
  location ~ \.php$ { include snippets/fastcgi-php.conf; fastcgi_pass unix:/run/php/php8.3-fpm.sock; }
  location ~ /\.(?!well-known) { deny all; }
}
```
`public/.user.ini` يرفع حدود الرفع لـ PHP-FPM (حجم ملف الاستيراد الأقصى يظهر بصفحة الاستيراد). في Nginx تأكد أن الجذر هو `public` فقط.

## التشخيص
* أخطاء التطبيق: `data/logs/app_errors.log` (JSON lines)، أو للأدمن: `GET /api/admin/errors?limit=50&level=EXCEPTION` (و`DELETE` للتفريغ).

## ما الذي تغيّر عن نسخة بايثون؟
**مقصود ومُحسَّن (لا يمس شكل الواجهة):**
1. SQLite → MySQL (نفس أسماء الجداول والأعمدة؛ الاستعلامات منقولة حرفياً مع مترجم لهجة داخلي) — الترتيب عند تساوي الأوقات يُثبَّت ليطابق SQLite.
2. التحصين ضد السباقات: خصم الرصيد عند الطلب ذرّي، استرداد الكوبون لا يتجاوز `max_uses`، المكافأة اليومية بقفل صف المستخدم، ملف اشتراكات الإشعارات بقفل.
3. إشعارات المهام الخلفية (اكتمال/استرجاع/فشل طلب معلّق) **تصل الآن**؛ في بايثون كانت تُفقد بصمت.
4. لا حسابات افتراضية معروفة: الأدمن يُنشأ من `config.php` (بدل `admin@admin.com / 2sebvWFr6BYwVBrV` و`test@test.com`).
5. **قسم الهدية اليومية بلوحة الأدمن** (`/api/admin/daily-gift`) كان يعطي خطأ 500 لكل الحسابات (يفحص عموداً غير موجود `users.role`) — أُصلح ويعمل الآن.
6. الأمان: ما ورد في قسم «الحماية» (حدود التخمين، CSRF، bcrypt، سجل التدقيق، إلغاء الجلسات، ترويسات).
7. تصغير أيقونة PWA بـ GD بدل Pillow (نفس القص والأحجام؛ البايتات تختلف).
8. **تغييرات واجهة وميزات مطلوبة صراحةً:** 2FA، الأجهزة والجلسات، خدمات الألعاب + المحادثة + تبويب «الألعاب» بطلباتي، الشعار المتحرك، «المزيد من الإعدادات»، المساعد الذكي بشكل جديد، أزرار وأيقونات جديدة، وعدم إظهار روابط الأقسام للمستخدم العادي. ومنيو سفلي للأدمن بدل الجانبي، ولوغو للألعاب.

**مُحافَظ عليه كما هو:** إدراج قيم بالقوالب بلا تهريب HTML، ونصوص أخطاء الشبكة (`requests`/`smtplib`) بصيغتها الأصلية. **صُحّح عن الأصل:** خصم المستوى لم يعد يُطبَّق مرتين (واجهة + خادم)، وطلب التعويض صار يرسل رقم الطلب عند المزوّد (لا رقم العرض)، واسترجاع المبلغ ذرّي (لا استرجاع مزدوج عند تزامن فحص الحالة مع الكرون)، ودالة «تواصل مع الدعم» المعطّلة بصفحة المعاملة المرفوضة.

## الاختبار
كل مسار قورن **جنباً إلى جنب مع تطبيق بايثون الأصلي** (نفس الطلب → مقارنة الحالة والترويسات والجسم حرفياً، وما يرسله كل تطبيق لمزوّد SMM/Binance/آسياسيل/تلغرام/SMTP، وفك تشفير Web Push) + اختبارات مخصصة للميزات الجديدة:
* `php tests/test_sqlsplit.php` · `php tests/test_transfer.php` · `php tests/test_security.php` (بلا قاعدة بيانات: مدقّق SQL، رفض الملفات الخبيثة، قنابل الضغط، عناوين IP، حدود المعدّل، bcrypt).
* `php tests/test_db.php` (طبقة قاعدة البيانات؛ **يمسح جداول** فلا يعمل إلا على قاعدة اسمها يحتوي `test`).
* صفحة `/app` مطابقة **بايتاً ببايت** لصفحة الأصل عدا الإضافات المقصودة (روابط الأقسام وصفحتا الاستيراد والأمان).
