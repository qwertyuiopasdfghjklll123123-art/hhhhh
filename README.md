# لوحة إدارة المشاريع الذكية

نظام لوحة تحكم وإدارة مشاريع بلغة PHP الخام (بدون أي إطار عمل خارجي) وقاعدة
بيانات MySQL، بتثبيت تلقائي كامل، إدارة مستخدمين وصلاحيات، وقسم "معرفة
المشروع" يربط كل مشروع بهيكل قاعدة بياناته وقواعده البرمجية ومستودع GitHub
الخاص به، مع مساعد ذكي بوضعين لكل مشروع: **دردشة عادية** (نص ورؤية، سياق
المشروع يُحقن تلقائياً)، و**وضع الكود** الذي يستكشف مستودع GitHub المرتبط
تلقائياً (أشبه بـ Claude Code) لحل المشاكل بناءً على محتوى الملفات الفعلي.

مزوّدو الذكاء الاصطناعي (عدة مفاتيح NVIDIA NIM، أو أي مزوّد آخر متوافق مع بنية
OpenAI Chat Completions API مثل OpenAI وGroq وDeepSeek) **عامّون على مستوى
النظام كله** ويديرهم الأدمن حصراً من صفحة واحدة، وتشاركهم كل المشاريع.
ربط GitHub يتم عبر **OAuth حقيقي** (زر "ربط GitHub" لكل مستخدم) بدل لصق
Personal Access Token يدوياً.

الواجهة مبنية بتصميم أسود بالكامل بأسلوب شبيه بـ Claude: قائمة جانبية ثابتة +
لوحة محتوى رئيسية، وداخل المساعد الذكي رواق محادثات + لوحة دردشة (تقسيم شاشة
من مستويين)، مع أزرار ملوّنة لكل إجراء (أساسي/نجاح/خطر/تحذير)، وخط IBM Plex
Sans Arabic، ودعم كامل لـ RTL ولشاشات الكمبيوتر المحمول والهواتف.

## المتطلبات

- PHP 8.1+ مع امتدادات: `pdo_mysql`, `curl`, `openssl`, `json` (مفعّلة افتراضياً في أغلب الاستضافات)
- MySQL 5.7+ أو MariaDB 10.3+
- خادم Apache (مرفق ملفات `.htaccess` جاهزة) أو Nginx/PHP-FPM
- لا حاجة لـ Composer أو أي حزم Node — المشروع PHP خام بالكامل

## التثبيت

1. ارفع محتويات المشروع إلى السيرفر (أو استنسخه داخل مجلد الاستضافة).
2. تأكد أن مجلد `config/` قابل للكتابة من قبل خادم الويب (سيُنشئ فيه المثبّت ملف `config.php`).
3. افتح المشروع من المتصفح — إن لم يوجد `config/config.php` سيتم توجيهك تلقائياً إلى `install.php`.
4. أدخل بيانات الاتصال بقاعدة البيانات (Host, Port, Name, User, Password). إن لم تكن قاعدة البيانات موجودة سيتم إنشاؤها تلقائياً (أو استخدام الموجودة إن لم تسمح صلاحيات المستخدم بإنشائها، كما هو الحال في بعض الاستضافات المشتركة).
5. أدخل بيانات حساب المسؤول الرئيسي (Admin): الاسم، البريد الإلكتروني، كلمة المرور.
6. عند الضغط على "ابدأ التثبيت" يقوم النظام بـ:
   - إنشاء/استخدام قاعدة البيانات وتنفيذ `database/schema.sql` بالكامل (كل الجداول بصيغة `IF NOT EXISTS`).
   - إنشاء حساب المسؤول بكلمة مرور مشفّرة (`password_hash` بخوارزمية BCRYPT).
   - توليد مفتاح تشفير عشوائي (32 بايت) وكتابة `config/config.php` تلقائياً.
7. سيتم توجيهك لصفحة تسجيل الدخول. سجّل الدخول بحساب المسؤول وابدأ العمل.

> لإعادة التثبيت من الصفر، احذف ملف `config/config.php` يدوياً من السيرفر.

### التثبيت اليدوي (اختياري)

يمكن نسخ `config/config.sample.php` إلى `config/config.php` وتعديله يدوياً، مع
استيراد `database/schema.sql` وإنشاء مستخدم مسؤول يدوياً عبر SQL باستخدام
`password_hash()` في PHP لتوليد كلمة المرور.

## معايير الأمان المطبّقة

- **PDO + Prepared Statements حصراً** في كل استعلام بقاعدة البيانات (`ATTR_EMULATE_PREPARES = false`) — لا استعلامات مُركَّبة من نصوص خام.
- **كلمات المرور**: `password_hash()` بخوارزمية BCRYPT، ومقارنة بـ `password_verify()`.
- **حماية CSRF**: رمز عشوائي 32 بايت لكل جلسة، يُتحقق منه في كل نموذج POST وكل طلب AJAX عبر ترويسة `X-CSRF-Token`.
- **حماية XSS**: تنظيف كل المخرجات عبر `htmlspecialchars()` (دالة `e()`)، وواجهة المساعد الذكي تبني عناصر DOM عبر `textContent` حصراً بدل `innerHTML` لأي نص قادم من المستخدم أو من رد النموذج الذكي.
- **جلسات آمنة**: أسماء جلسة مخصّصة، `HttpOnly` + `SameSite=Lax` + `Secure` عند HTTPS، `session_regenerate_id()` عند تسجيل الدخول، ومهلة خمول تلقائية.
- **الحماية من هجمات التخمين (Brute-force)**: قفل مؤقت بعد 5 محاولات فاشلة لكل مزيج (IP + بريد إلكتروني).
- **تشفير الأسرار في قاعدة البيانات**: مفاتيح كل مزوّدي الذكاء الاصطناعي (`ai_providers.api_key`)، رمز وصول GitHub OAuth لكل مستخدم (`users.github_oauth_token`)، وClient Secret الخاص بتطبيق GitHub OAuth (`app_settings`) — كلها مشفّرة (AES-256-GCM) بمفتاح مولَّد تلقائياً أثناء التثبيت ومحفوظ في `config/config.php` فقط (خارج المستودع). القيم المشفّرة **لا تُفَكّ ولا تُعرض للمتصفح إطلاقاً** بعد الحفظ — الحقول تظهر فارغة مع إشعار "محفوظ".
- **مفاتيح الـ API لا تصل للمتصفح مطلقاً**: كل نداء لـ GitHub ولأي مزوّد ذكاء اصطناعي يتم من السيرفر (PHP) حصراً؛ متصفح المستخدم لا يرى المفتاح لا في HTML ولا في طلبات AJAX.
- **ربط GitHub عبر OAuth حقيقي**: بدل لصق Personal Access Token يدوياً، يربط كل مستخدم حسابه عبر Authorization Code Flow القياسي (`github_oauth_start.php` → GitHub → `github_oauth_callback.php`)؛ رمز `state` عشوائي بالجلسة يمنع CSRF، ومسار العودة (`return`) يُتحقَّق منه بتعبير نمطي صارم يمنع Open Redirect.
- **صلاحيات الوصول**: `users.php`، `ai_providers.php`، و`admin_settings.php` محمية بـ `require_admin()` (الأدمن حصراً — يدير المزوّدين وتطبيق GitHub OAuth). صفحات المشاريع محمية بـ `require_login()` مع تحقق إضافي من الملكية أو دور المسؤول قبل الأرشفة أو الحذف.
- **ترويسات أمان HTTP**: `X-Content-Type-Options`, `X-Frame-Options: DENY`, `Referrer-Policy`, `Content-Security-Policy`, `Permissions-Policy` على كل صفحة.
- **حماية على مستوى الملفات**: `.htaccess` يمنع الوصول المباشر لمجلدات `config/` و`includes/` و`services/` و`database/` وأي ملف إعداد أو SQL.

## مزوّدو الذكاء الاصطناعي (عامّون على مستوى النظام)

من صفحة **"مزوّدو الذكاء الاصطناعي"** (`ai_providers.php`، للأدمن فقط) تُدار
كل مزوّدي الذكاء الاصطناعي على مستوى النظام كله — لا لكل مشروع على حدة. يمكن
إضافة أي عدد من المفاتيح: أكثر من مفتاح NVIDIA NIM (للتبديل بينها أو كنسخة
احتياطية)، أو أي مزوّد آخر متوافق مع بنية OpenAI Chat Completions API (OpenAI،
Groq، DeepSeek، Together AI، OpenRouter، Mistral، أو نموذج مستضاف ذاتياً)
بتحديد نقطة الاتصال (Base URL) الخاصة به. كل مزوّد له تسمية، مفتاح API خاص،
نموذج نص، ونموذج رؤية اختياري، ويمكن تعيين واحد كـ"افتراضي". هذه القائمة
مشتركة بين كل المشاريع وكلا وضعي المحادثة — من تبويبَي "الدردشة العادية" و"الكود"
في كل مشروع تظهر قائمة منسدلة لاختيار أي مزوّد مُسجَّل تريد استخدامه لكل رسالة.

## ربط حساب GitHub (OAuth)

1. **إعداد لمرة واحدة (أدمن):** من صفحة "إعدادات النظام" (`admin_settings.php`)،
   سجّل تطبيق OAuth من `github.com/settings/developers` → New OAuth App، بحقل
   Authorization callback URL مطابق تماماً لما تعرضه الصفحة، ثم احفظ Client ID
   وClient Secret الناتجين هناك.
2. **لكل مستخدم:** زر "ربط حساب GitHub" (في تبويب "السياق والإعدادات" لأي مشروع،
   أو من "حسابي") يحوّل إلى GitHub لتفويض الوصول (Authorization Code Flow
   القياسي)، ثم يعود ويخزّن رمز الوصول مشفّراً على حساب المستخدم — لا حاجة لإنشاء
   أو لصق Personal Access Token يدوياً بعد الآن. نفس الحساب المرتبط يُستخدم
   تلقائياً لكل مشاريع هذا المستخدم.
3. لكل مشروع، يبقى تحديد **Owner/Organization، اسم المستودع، والفرع** من تبويب
   "السياق والإعدادات" (حقول نصية بسيطة، دون أي Token يدوي).

## تبويبات كل مشروع (`project_context.php`)

1. **الدردشة العادية** — محادثة نصية/برؤية عادية؛ `AiClient::buildSystemPrompt()`
   يحقن هيكل قاعدة البيانات وقواعد المشروع (وملف GitHub المُرفَق يدوياً إن وُجد)
   تلقائياً ضمن System Prompt، مع إمكانية إرفاق صورة لتحليلها عبر نموذج رؤية،
   وزر "رفع إلى GitHub" على أي كتلة كود في رد المساعد لإنشاء Commit مباشر على
   الفرع المحدد (يحدَّد الملف الموجود تلقائياً لتحديثه، أو يُنشأ كملف جديد).
2. **الكود** — مساعد أشبه بـ Claude Code: يتطلب حساب GitHub مرتبطاً ومستودعاً
   محدَّداً لهذا المشروع. عند كل رسالة يجلب `GithubClient::getTree()` نظرة عامة
   عن ملفات المستودع (حتى 500 ملف) ويحقنها بموجّه النظام، ثم يعمل بحلقة
   استكشاف **محدودة**: إن احتاج النموذج الاطلاع على ملف معيّن يطلبه بصيغة نصية
   خاصة (`READ_FILE: path`، حتى 3 ملفات دفعة واحدة)، فيجلبه السيرفر عبر
   `GithubClient::getFile()` ويزوّده به في جولة تالية — بحد أقصى **3 جولات
   استكشاف** إجمالاً لكل رسالة (لضبط الكلفة/الزمن وتفادي حدود تنفيذ PHP على
   الاستضافات المشتركة)، ثم رد نهائي يتضمّن أي كود مقترح جاهزاً للنسخ أو الرفع.
   لا تُخزَّن جولات القراءة الوسيطة في سجل المحادثة — فقط طلب المستخدم والرد
   النهائي (مع ملاحظة شفّافة بأسماء الملفات التي اطّلع عليها المساعد).
3. **السياق والإعدادات** — بيانات المشروع، هيكل قاعدة البيانات (SQL Schema)،
   قواعد المشروع البرمجية (System Rules)، وبيانات GitHub (Owner/Repo/Branch
   + حالة ربط الحساب).

## الترقية من نسخة سابقة

إن كنت قد ثبّتّ نسخة سابقة من النظام (بها `config/config.php` موجود بالفعل)
وكانت مزوّدو الذكاء الاصطناعي فيها لا تزال لكل مشروع على حدة، شغّل
`database/migrate_global_providers_and_oauth.sql` **مرة واحدة فقط** على قاعدة
بياناتك (عبر تبويب SQL في phpMyAdmin، أو
`mysql -u USER -p DBNAME < database/migrate_global_providers_and_oauth.sql`).
آمن تماماً على بياناتك الحالية: كل مزوّدي الذكاء الاصطناعي المحفوظين مسبقاً في
كل مشاريعك يُنقَلون بالكامل إلى القائمة العامة الجديدة دون فقدان أي منها
(الجدول القديم يُعاد تسميته فقط وليس حذفه)، ويُضاف عمود `mode` لجدول
`ai_conversations` وعمودا `github_oauth_token`/`github_oauth_username` لجدول
`users` وجدول `app_settings` الجديد. بعد الترقية، فعّل ربط GitHub عبر OAuth
(القسم أعلاه) إن رغبت — بيانات GitHub اليدوية (Owner/Repo/Branch) المحفوظة سابقاً
لكل مشروع تبقى كما هي.
